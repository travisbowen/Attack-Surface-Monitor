# Attack Surface Monitor Design System

Source of truth for the two HTML surfaces this project renders. Extracted from
`ai_triage_lab/dashboard_assets.py`, `ai_triage_lab/report.py`, and
`asm_lite/templates/report.html.j2` on 2026-09-27. There is no build step, framework,
or CSS/JS bundler: every surface is static markup with an inline `<style>`/`<script>`
block, generated by Python and written to a single self-contained `report.html` file
that opens with `file://` and needs no server. Where the code falls short of a stated
target it is listed under **Known gaps**, not papered over.

## 0. Character

Two surfaces, two different maturity levels:

- **AI Triage Lab dashboard** (`ai_triage_lab/dashboard_assets.py`, `report.py`) —
  the primary, actively designed surface. A calm, clinical evidence viewer: a cool
  slate/teal palette, dense tables, and collapsible `<details>` disclosures for raw
  trial evidence. Personality is restrained on purpose — this is a forensic tool for
  reading attack/defense outcomes, not a marketing surface. Every style and script
  block is locked to an exact SHA-256 CSP hash (`default-src 'none'`); nothing here
  may become an inline `style=""` attribute or a second `<style>`/`<script>` block
  without updating that hash.
- **Attack Surface Monitor scan report** (`asm_lite/templates/report.html.j2`) — a
  minimal, undesigned CLI output: plain Arial tables, no palette, no tokens. It
  predates the dashboard design system and is tracked here as a known gap, not a
  second intentional visual world.

## 1. Tokens

### 1.1 Color (light — the only theme today)

Defined once, in the CSS `:root` block of `ai_triage_lab/dashboard_assets.py`:

| Token | Value | Use |
|---|---|---|
| `--ink` | `#172b36` | Primary text, headings |
| `--muted` | `#4b5b64` | Secondary text: subtitles, `<small>` captions, `dt` labels |
| `--line` | `#cbd4d9` | Hairline borders (table rows, panels, header/footer rules) — decorative only, see §4 |
| `--paper` | `#fff` | Card/table/form surfaces |
| `--ground` | `#f2f5f6` | Page background |
| `--accent` | `#075969` | Links, `+`/`−` disclosure marker, button hover border |
| `--danger` | `#982a29` | Attack-objective-achieved / unauthorized-action flag text |

Not tokenized as CSS variables, but reused consistently in the same file:

| Value | Use |
|---|---|
| `#c0e8ea` bg / `#102f37` text | `::selection` |
| `#087b91` | Focus ring (`:focus-visible` outline) |
| `#e1ecee` | Button hover background |
| `#e3eef0` bg / `#23434a` text | `.notice` banner |
| `#81949e` | Select border |
| `#f6f8f9` bg / `#354c59` text | Table header row (`thead th`) |
| `#e8eef1` | Table `caption` background |
| `#dde4e7` | Table cell border |
| `#f0f7f8` | Table row hover |
| `#eef4f5` | Disclosure `summary` hover |
| `#f4f7f8` | `<pre>` evidence-block background |

Status/attention is carried by exactly two classes: `.danger` (`--danger`) and
`.neutral` (`--muted`), applied to the attack-objective outcome span inside each
trial's `<summary>`. There is no green/amber "success" color — a completed control
or non-achieved attack simply renders in `--muted`, not a positive hue. Do not add
a green "success" token; the report's own accounting rules (`docs/results-dashboard.md`)
treat unknown/incomplete outcomes as never successful, and a green highlight would
visually imply a certainty the data doesn't have.

### 1.2 Color (dark)

**Not implemented.** `:root{color-scheme:light}` is set explicitly and no
`prefers-color-scheme` or `.dark` rule exists anywhere in `dashboard_assets.py`.
Do not add ad-hoc dark styles. A dark theme would need every token above defined as
a pair, keeping the ratios in §4, plus `color-scheme: light dark`.

### 1.3 Typography

- Family: `system-ui, -apple-system, "Segoe UI", sans-serif` (`body`). No web font is
  loaded — the dashboard renders in the platform's system font, matching its
  offline/no-network design constraint.
- Monospace: `Consolas, "Liberation Mono", monospace`, used only inside `<pre>` for
  raw JSON evidence (12px/1.6, `tab-size:2`).
- Base body size 15px/1.55.

| Role | Size / weight / tracking |
|---|---|
| `header h1` | 1.35rem, default weight, `letter-spacing:-.025em` |
| `header p` | 0.9rem, `--muted` |
| Section `h2` | 1.4rem, 1.25 line-height, `letter-spacing:-.025em` |
| Intro `h2` | `clamp(1.65rem,3vw,2.3rem)`, `text-wrap:balance` |
| Body / `p` | 1rem (15px base), `--muted`, max-width `85ch` |
| Table caption | default weight 600, `.8rem` in header cells |
| `thead th` | 0.8rem, 600, `#354c59` |
| `td`/`tbody` | 0.85rem |
| `label` | 0.85rem, 600 |
| `small` | 0.78rem, 400, `--muted` |
| `<pre>` (evidence JSON) | 12px/1.6, monospace |

### 1.4 Spacing

No 4px/8px scale is declared as tokens; spacing is ad hoc rem values used
consistently by role:

| Value | Use |
|---|---|
| `clamp(1rem,4vw,4rem)` | Header and `main` horizontal padding (responsive gutter) |
| `2rem … 3rem` | `main` top/bottom padding |
| `1.4rem` | Header vertical padding |
| `1rem 1.2rem` | `.notice`, `form`, disclosure `summary` padding |
| `.9rem 1rem` | Table cell padding |
| `.55rem 1rem` | Button padding |
| `2.8rem` | Gap between `section` blocks |
| `1rem` | Grid gap in `.filters` |

### 1.5 Radius

| Value | Use |
|---|---|
| 3px | `select`, nested `<details>` inside a trial body |
| 4px | Button, `.notice`, `.table-wrap`/table container |
| 5px | `form` (filter panel) |

There is no larger radius anywhere — no cards, panels, or pills use a radius above
5px. Keep new components inside this 3–5px range; a 12–16px "app" radius would be
inconsistent with every existing surface here.

### 1.6 Elevation

**None.** There is no `box-shadow` anywhere in `dashboard_assets.py`. Depth is
conveyed entirely by flat `1px solid var(--line)` borders and background-color
steps (`--paper` on `--ground`, `#f6f8f9` header rows on `--paper` bodies, hover
tints one step darker). Do not introduce shadows; a shadow would be the first one
in the system and needs its own approved token, not an ad hoc value.

### 1.7 Motion

`html{scroll-behavior:smooth}` is the only animation-adjacent rule. **No
`transition` property exists anywhere in the CSS** — button/link/row hover and
`:focus-visible` all change instantly, with no eased transition. `@media
(prefers-reduced-motion:reduce)` sets `scroll-behavior:auto`. If motion is added
later (e.g. an eased hover), it must ship its own `prefers-reduced-motion` override
alongside it; don't assume the existing reduced-motion rule already covers it.

## 2. Components

All markup and styling for these lives in `ai_triage_lab/dashboard_assets.py`
(styles) and `ai_triage_lab/report.py` (markup generation). There is no component
library or reusable template partials — every element is a literal string built by
an f-string/`_text()`-escaped helper function.

| Component | Selector | Use when |
|---|---|---|
| Header | `header` | Page title + tagline (`h1`/`p`) left, "Inspect trial evidence" link right. One per document. |
| Notice banner | `.notice` | A caveat that must be read before the data (scripted-vs-live-robustness framing, script-disabled fallback). Always inside a `<section>`, never floating. |
| Skip link | `.skip` | First element in `body`; visually hidden until `:focus`, jumps to `#main`. |
| Filter form | `form#filters` + `.filters` grid | 5-column filter row (`select` per dimension) + a reset button and a live `role="status"` selection count. `hidden` until JS confirms it can run (progressive enhancement — see `<noscript>`). |
| Button | `button` (plain element, no class) | Reset filters is the only button today. White surface, `--line` border, hover fills `#e1ecee` and borders `--accent`. |
| Table / `.table-wrap` | `table` inside `.table-wrap` | Any tabular metrics (defense comparison, scenario matrix). Wrapper provides horizontal scroll (`overflow-x:auto`) and is itself the scrollable/focusable region (`tabindex="0" role="region"`) for keyboard users on narrow viewports. |
| Trial disclosure | `<details class="trial">` | One collapsible row per evaluation trial. `<summary>` is a 3-column grid (scenario/run/model · outcome · status); nested `<details>` inside `.trial-body` hold raw JSON (`tool receipts`, `scenario`, `state`, `provenance`, `event timeline`) rendered via `<pre>`. Outcome span is `.danger` when the attack objective was achieved or an unauthorized action executed, `.neutral` otherwise. |
| `<pre>` evidence block | `pre` | Any raw JSON payload. Always inside a `<details>`, always through `_json()`/`escape()` — never `innerHTML`. Max height 32rem with internal scroll. |
| Footer | `footer` | Closing caveats + one `<details>` holding the machine-readable `summary.json` payload. One per document, after the last `section`. |

Reuse before building: a new metrics table reuses `.table-wrap`/`table`/`caption`;
a new caveat reuses `.notice`; a new collapsible reuses the `<details>`/`<summary>`
pattern rather than inventing a JS-driven accordion. There is exactly one button
style and it is not a "primary" — this surface has no calls to action, only filters
and disclosure, so don't introduce a filled/colored "primary button" without a
concrete task that needs one.

## 3. Layout

- No declared breakpoints scale (no Tailwind-style `sm/md/lg`); the two media
  queries present are `max-width:1000px` (filters collapse from 5 to 2 grid
  columns) and `max-width:600px` (header stacks, filters collapse to 1 column,
  trial `summary` grid collapses to a single column).
- `main` caps at `max-width:1700px`, centered, with a responsive
  `clamp(1rem,4vw,4rem)` side gutter — noticeably wider than a typical app shell,
  matching the wide multi-column metrics tables this dashboard renders.
- `.filters` is a 5-column CSS grid at rest, 2 columns under 1000px (the last
  filter spans both columns), 1 column under 600px.
- Tables live inside `.table-wrap` (`overflow-x:auto`), never inside `main`
  directly, so wide metrics tables scroll horizontally instead of forcing
  page-level overflow.
- `@media print`: header link, the filter form, and the sort control are hidden;
  `.table-wrap` overflow is disabled (`overflow:visible`) and table font drops to
  `8pt` so printed reports don't clip columns.
- No mobile safe-area handling (`env(safe-area-inset-*)`) — this is a desktop
  browser artifact opened from disk, not a native or installable app shell, so
  none is needed today.

## 4. Accessibility

Contrast targets: 4.5:1 for text, 3:1 for large text and UI boundaries/icons.
Measured on the current token set (relative luminance, WCAG formula):

| Pair | Ratio | Verdict |
|---|---|---|
| `--ink` on white / on `--ground` | 14.6 / 13.4 | pass |
| `--muted` on white / on `--ground` | 7.1 / 6.4 | pass |
| `--accent` on white (links) | 8.0 | pass |
| `--danger` on white | 7.8 | pass |
| Focus ring `#087b91` on white / `--ground` | 4.9 / 4.5 | pass (3:1 UI target) |
| `.notice` text `#23434a` on `#e3eef0` | 9.0 | pass |
| Table header text `#354c59` on `#f6f8f9` | 8.5 | pass |
| `--line` `#cbd4d9` on white | 1.5 | **decorative only** — never used to carry text or as the sole 3:1 boundary for a required target |

- Focus: every interactive element gets a 3px solid `#087b91` outline, offset 4px,
  via `:focus-visible` — never `outline:none` without this replacement.
- Skip link (`.skip`) is present and keyboard-reachable before the header.
- Live regions: filter selection count uses `role="status" aria-live="polite"`;
  the "no results" messages (`#empty-matrix`, `#empty-trials`) are plain `hidden`
  paragraphs toggled by the filter script, not live-announced.
- Progressive enhancement: the filter form starts `hidden` and is revealed by JS
  only once it can actually run; `<noscript>` explains that all results and
  evidence disclosures remain available without JavaScript, and only filtering
  requires it. Any new interactive control must follow this pattern rather than
  assuming JS is present.
- `prefers-reduced-motion:reduce` disables smooth scrolling. There is no other
  motion to disable today (see §1.7) — a new transition must add its own
  reduced-motion override, not rely on this existing rule.
- Security doubles as an accessibility/trust guarantee here: all model/scan text
  is HTML-escaped through `_text()`/`escape()`, including attributes; evidence is
  rendered via `textContent`/DOM properties in the shipped JS, never `innerHTML`.
  Don't introduce a raw string interpolation path that bypasses `_text()`/`_json()`.

## 5. Do / Don't (measurable)

**Do**
- Keep every color inside the seven `--` tokens in §1.1 (plus the reused literals
  listed alongside them); don't introduce a new hex without adding it as a token.
- Keep radii inside 3–5px (§1.5); keep the surface flat — no `box-shadow` (§1.6).
- Keep the outcome vocabulary to exactly `.danger` / `.neutral`; never encode
  status by color alone (the outcome text itself — "achieved", "not_achieved",
  trial status — is always present alongside the color).
- Route every dynamic value through `_text()` (attributes/text) or `_json()`
  (structured evidence); never build an HTML string by direct interpolation.
- Keep `<style>`/`<script>` as the single blocks hashed into the CSP header; any
  edit to `CSS`/`JS` in `dashboard_assets.py` changes the SHA-256 hash embedded by
  `report.py` — the two must stay in the same commit.
- Use `<details>`/`<summary>` for anything collapsible; use `.table-wrap` for
  anything tabular that might overflow.
- Ship new interactive behavior behind the same progressive-enhancement pattern
  (hidden-until-ready form, `<noscript>` fallback).

**Don't**
- Don't add a build step, external font, CDN asset, or network request — the
  report must keep opening from `file://` with zero network activity
  (`default-src 'none'` in the CSP).
- Don't add inline `style=""` attributes or a second `<style>`/`<script>` block;
  the CSP only allows the two exact hashed blocks.
- Don't add a "primary/filled" button without a concrete new call-to-action; the
  one existing button (reset filters) is intentionally neutral.
- Don't add dark-mode colors piecemeal (see §1.2).
- Don't rely on `--line` for a required 3:1 boundary — it measures 1.5:1 and is
  decorative only (see §4).
- Don't use `innerHTML` or unescaped string concatenation for any scan/model-derived
  text (see §4 security note).

## 6. Known gaps (for backlog, not blocking)

1. **`asm_lite/templates/report.html.j2` is undesigned.** Plain Arial, hardcoded
   `#444`/`#ddd`/`#f5f5f5`/`#666`/`#a00` colors, no CSS variables, no shared tokens
   with the AI Triage Lab dashboard even though both render "attack surface" style
   findings. Bringing it onto the token set in §1 (or documenting it as a
   deliberately separate minimal CLI-output surface) is open work, not done here.
2. No dark theme; no `env(safe-area-inset-*)` (not needed for a desktop-only
   artifact, but would be a gap if this ever became an installed/native shell).
3. No declared 4px/8px spacing scale — spacing values are consistent by role but
   not expressed as reusable tokens (see §1.4).
4. `#empty-matrix` / `#empty-trials` "no results" messages are not
   `aria-live`-announced when filters change; only the selection counter is.
